# Folder Structure

## Purpose
This document explains the approved repository layout so every contributor knows where new code, tests, and docs belong without guessing or duplicating structure ad hoc.

## Scope
Covers the repository's physical folder layout: `frontend/`, `backend/`, `docs/`, and `cicd/`, and the rules for adding new folders.

**Out of scope:** file/variable/class naming rules (see [NamingConventions.md](NamingConventions.md)) and architectural rationale (see [Architecture.md](Architecture.md)).

## When to Update This Document
- A new top-level folder is added.
- A new backend module or frontend feature folder is introduced.
- An existing folder is renamed, moved, or removed.

## Recommended Sections
- Repository Tree
- Frontend Structure (web / mobile / shared)
- Backend Structure (modules, shared, database)
- Docs Structure
- CI/CD Structure
- Rules for Adding New Folders
