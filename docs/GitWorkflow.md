# Git Workflow

## Purpose
This document defines how the team branches, commits, and reviews code so a 3-person team avoids collisions and keeps `main` always deployable.

## Scope
Covers branching strategy, commit message conventions, pull request process, and merge strategy.

**Out of scope:** CI/CD pipeline mechanics (see [Deployment.md](Deployment.md) and `cicd/scripts/`).

## When to Update This Document
- The branching model changes.
- The PR review/approval process changes.
- A recurring merge/process problem prompts a new rule.
