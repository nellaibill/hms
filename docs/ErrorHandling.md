# Error Handling

## Purpose
This document defines a consistent approach to handling and surfacing errors across frontend and backend, so failures are predictable and debuggable rather than handled ad hoc per module.

## Scope
Covers backend error handling strategy, the standard error response shape, and frontend error handling/messaging.

**Out of scope:** logging mechanics (see [Logging.md](Logging.md)) and the API error response contract details, which are shared with (see [ApiStandards.md](ApiStandards.md)).

## When to Update This Document
- A new class of error or handling pattern is introduced.
- The standard error response shape changes.
- User-facing error messaging guidelines change.
