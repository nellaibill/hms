# Architecture

## Purpose
This document is the single source of truth for the system's high-level architecture. It exists so every team member — especially junior developers — shares the same mental model of how the system is structured, without needing to reverse-engineer it from code.

## Scope
Covers system-wide architectural concerns only: architecture style, technology stack, module boundaries, and high-level data flow.

**Out of scope:** module-internal business logic, coding style (see [CodingStandards.md](CodingStandards.md)), deployment topology (see [Deployment.md](Deployment.md)), and rationale for individual decisions (see [DecisionLog.md](DecisionLog.md)).

## When to Update This Document
- A new module is added, removed, or renamed.
- A module boundary or cross-module dependency rule changes.
- The technology stack changes (e.g., new major dependency, new runtime version).
- A recorded decision in `DecisionLog.md` affects the high-level architecture.

## Recommended Sections
- Overview
- Architecture Style (Modular Monolith rationale)
- Technology Stack
- Module Boundaries
- High-Level Diagram
- Cross-Module Communication Rules
- Future Considerations (explicitly deferred approaches)
