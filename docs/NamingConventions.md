# Naming Conventions

## Purpose
This document prevents inconsistent naming across frontend, backend, and database layers — a common source of confusion when junior developers work across the stack without a shared reference.

## Scope
Covers naming rules for files, folders, variables, classes, interfaces, API routes, DTOs, and database objects.

**Out of scope:** general code style/formatting (see [CodingStandards.md](CodingStandards.md)).

## When to Update This Document
- A new type of artifact (e.g., a new kind of module file) needs a naming rule.
- Inconsistent naming is found during code review and a rule is agreed on to prevent recurrence.

## Recommended Sections
- General Rules
- Frontend Naming (files, components, hooks, folders)
- Backend Naming (classes, interfaces, namespaces, projects)
- Database Naming (schemas, tables, columns)
- API Naming (routes, DTOs, query parameters)
- Examples
